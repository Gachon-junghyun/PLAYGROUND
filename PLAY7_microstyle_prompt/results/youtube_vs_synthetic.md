## 자막 입력의 한계 — 모델이 헷갈리는 케이스

자막은 **방송 host 멘트**가 많다. 모델은 입력을 "친구 톡"으로 가정하기 때문에 의도 추론 실패가 생긴다.

- **[YT-02]** 영상 host 의 도입 멘트 → 모델은 친구 푸념으로 해석
  - IN: `어색해지는 순간이 있습니다`
  - REPLY: ㄴㄴ 나만 그런 거 아니지?
- **[YT-11]** host의 "긴장된다" 멘트 → 모델은 "힘듦"으로 진지 해석
  - IN: `그래서 제가 오늘 조금 힘이 들어가 있는데요.`
  - REPLY: 많이 힘들구나, 무슨 일 있어?
- **[YT-21]** 비유적 표현이지만 모델은 진지로 잡음
  - IN: `밖은 너무 무서운 전쟁터였어`
  - REPLY: 많이 힘들었겠다.
- **[YT-27]** host self-talk → 모델은 친구의 명령으로 해석
  - IN: `헛소리 그만하고 빨리 본론으로 가도록 하겠습니다.`
  - REPLY: 혹시 저한테 보고서 같은 거 제출하라는 건가요?

→ Phase 2 데이터셋 구축 시 "방송 host 멘트는 case로 부적합" 룰 필요. 추출 휴리스틱에 "가벼운 1인칭 푸념·받아치기 패턴" 필터 강화.

## 두 평가셋이 보여준 다른 모습

| 항목 | 합성 50건 | 자막 30건 |
|---|---|---|
| 입력 정제도 | 깨끗 | 자동전사 오탈자 다수 |
| 입력 다양성 | 카테고리 9종 균등 분포 | 방송 host 멘트 편중 |
| 안전성 검증 | 명시적 risk=high 라벨로 가능 | 정답 라벨 없음, 사람 spot-check 필수 |
| 펀치라인 발상 | 모델이 안전한 비유 (신발끈, 배터리) | 모델이 더 과감 (국가 단위, 거울 메타포) |
| Speaker 이모지 슬립 | 1/50 (2%) | 2/30 (7%) |
| latency | 13.3s/case | 11.5s/case (자막이 짧음) |

## Phase 2 데이터셋 구축에 주는 시그널

1. **자막 candidates에서 친구 톤 발화 선별 필터 필요** — 방송 host 멘트는 input으로 부적합. 
   필터 후보: 1인칭 푸념 (~듯, ~한 것 같아), 짧은 반응 (~지?, 엥?), 자조 (~고 있어).
2. **자동전사 오탈자는 학습 데이터의 노이즈가 아니라 강건성 신호로 활용** — 모델이 "모름을 인정하고 받아침" 패턴을 학습할 수 있다.
3. **모델의 펀치라인 발상은 입력의 다양성과 비례** — 합성 50건보다 자막 30건에서 더 신선한 비유. 데이터 다양성이 핵심.
4. **Speaker prompt 이모지 차단 강화 필요** — "입력에 이모지 없으면 절대 사용 금지" 명시 추가.
5. **안전성 평가는 합성 데이터로**, **표현력 평가는 자막 데이터로** 분리하는 게 합리적.
