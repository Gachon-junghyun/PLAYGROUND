# Korean Microstyle LLM Project

## 한 줄 정의

재미있는 문장을 외우는 LLM이 아니라, 상황을 보수적으로 판단한 뒤 사람처럼 짧고 말맛 있게 반응하는 한국어 대화 모델을 만든다.

핵심은 "웃긴 답변 생성기"가 아니라 "눈치 보고 웃기는 모델"이다.

## 문제의식

일반적인 LLM 답변은 너무 완벽하고 매끈해서 실제 사람 대화의 느낌이 약하다. 사람들은 항상 완성된 문장으로 말하지 않는다.

실제 대화에는 다음과 같은 짧은 신호가 많다.

- ㄱㄱ
- ㄴㄴ
- ㅇㅋ
- ㅇㅈ
- ㄹㅇ
- ㄱㅊㄱㅊ
- 아냐아냐
- 근데 그러면
- 쉽지 않음

이런 표현들은 단순한 축약어가 아니라 관계, 감정, 동의, 거절, 위로, 장난, 회피 같은 사회적 기능을 수행한다.

## 목표

한국어 대화에서 다음 능력을 가진 작은 모델을 만든다.

- 사용자 입력의 감정과 상황을 보수적으로 판단한다.
- 농담이 허용되는 상황인지 먼저 본다.
- 친절한 말, 재미있는 말, 짧은 말, 능청스러운 말을 구분한다.
- `ㄱㄱ`, `ㄴㄴ`, `ㅇㅋ` 같은 미세 반응을 상황에 맞게 쓴다.
- 완벽한 문장보다 실제 사람 같은 불완전한 구어체를 자연스럽게 사용한다.
- 대화를 끊지 않고 이어가게 만든다.

## 전체 구조

모델은 두 개의 레이어로 동작한다.

```text
사용자 입력
→ Thinker: 눈치/상황 판단
→ Speaker: 말맛 있는 문장 생성
→ 최종 답변
```

### Thinker

Thinker는 재미있게 말하지 않는다. 건조하고 보수적으로 판단한다.

역할:

- 상황 분류
- 감정 분류
- 관계 거리 판단
- 답변 기능 선택
- 유머 허용 범위 판단
- 피해야 할 말투 판단

예시:

```json
{
  "input": "나 오늘 발표 망한 듯",
  "output": {
    "emotion": ["민망함", "불안"],
    "context": "작은 실패",
    "relationship": "친한 대화",
    "reply_function": ["위로", "긴장 완화"],
    "humor_level": "light",
    "allowed_style": ["다정함", "능청", "짧은 비유"],
    "avoid": ["조롱", "과한 밈", "실패 확정"]
  }
}
```

### Speaker

Speaker는 Thinker의 판단 안에서만 재미있게 말한다.

역할:

- 짧고 자연스러운 한국어 답변 생성
- 말투 장치 적용
- 초성/압축어 사용
- 비유, 능청, 완곡화, 축소 표현 사용
- 위험한 상황에서는 재미를 줄이고 안정적으로 답변

Speaker LoRA 데이터는 Thinker보다 넓게 넣는다. Speaker는 판단 모델이 아니라 표현 모델에 가깝기 때문에, 다양한 말투와 리액션 재료를 많이 먹이는 것이 도움이 된다.

다만 모든 데이터를 한 통에 그대로 섞으면 말투가 뭉개질 수 있다. 침착맨식 건조함, 뜬뜬식 편한 수다, 차쥐뿔식 고에너지, 피식대학식 캐릭터 연기를 구분하지 않고 넣으면 모델이 한 답변 안에서 서로 다른 말투를 뒤섞을 수 있다.

따라서 Speaker 데이터는 많이 넣되, 모든 샘플에 최소한의 `style_control` 태그를 붙인다.

예시:

```json
{
  "input": {
    "utterance": "나 오늘 발표 망한 듯",
    "judgment": {
      "reply_function": ["위로", "긴장 완화"],
      "humor_level": "light",
      "allowed_style": ["다정함", "능청", "짧은 비유"],
      "avoid": ["조롱", "과한 밈"]
    },
    "style_control": {
      "source_style": "dry_talk",
      "energy": "low",
      "tone": ["건조함", "능청", "다정함"],
      "compression": "medium",
      "dialogue_type": "natural_dialogue"
    }
  },
  "output": "ㄱㅊㄱㅊ 망한 게 아니라 발표가 잠깐 신발끈 밟은 거임."
}
```

Speaker용 최소 컨트롤 태그:

- `source_style`: dry_talk, friendly_talk, high_energy, sketch, interview, user_anchor
- `energy`: low, medium, high
- `humor_level`: none, light, medium, high
- `relationship`: formal, casual, close
- `dialogue_type`: natural_dialogue, broadcast_talk, sketch, interview
- `risk`: low, medium, high

Speaker LoRA에는 기본적으로 좋은 출력만 넣는다. 나쁜 답변은 Speaker가 따라 배울 수 있으므로, Thinker나 평가 모델 쪽에서 "피해야 할 예시"로 사용한다.

정리하면 Thinker 데이터는 적고 정확하게, Speaker 데이터는 넓고 다양하게 간다. 단, Speaker 데이터에는 반드시 말투 이름표를 붙인다.

## 기존 파인튜닝과의 차이

일반적인 파인튜닝:

```text
입력 → 좋은 답변
```

이 프로젝트:

```text
입력
→ 상황/감정/관계/위험도/말투 허용 범위
→ 말맛 있는 답변
```

차이점:

- 문체를 복제하는 것이 아니라 말투 선택 규칙을 학습한다.
- 재미있는 문장 자체보다 재미가 허용되는 조건을 학습한다.
- 좋은 답변뿐 아니라 피해야 할 답변도 데이터에 포함한다.
- 짧은 반응을 사회적 행동 단위로 다룬다.

## HER에서 가져올 아이디어

HER 프로젝트는 역할극 학습을 위해 dual-layer thinking을 사용한다.

HER식 구조:

```text
system_thinking
role_thinking
role_action
dialogue
```

우리 프로젝트에서는 이것을 한국어 말맛 학습용으로 바꾼다.

우리식 구조:

```text
situation_judgment
style_judgment
safety_judgment
reply
```

HER처럼 원문 대화에 "생각"을 붙이되, 긴 내면 독백이 아니라 학습 가능한 분류형 판단으로 만든다.

## 데이터베이스 설계

많은 데이터보다 분류가 중요하다. 데이터베이스는 사전식 뜻풀이가 아니라 말의 사회적 기능과 반응을 저장한다.

### Micro-Reaction Entry

```json
{
  "utterance": "ㄱㅊㄱㅊ",
  "expanded": "괜찮아 괜찮아",
  "function": ["위로", "완화", "수습"],
  "tone": ["캐주얼", "다정함", "짧음"],
  "context": ["실수", "민망함", "작은 실패"],
  "avoid_context": ["큰 슬픔", "공식 사과"],
  "expected_effect": ["부담 감소", "대화 지속"],
  "style_neighbors": ["ㄱㅊ", "아냐 괜찮아", "노상관"],
  "reply_templates": [
    "ㄱㅊㄱㅊ 이건 수습 가능",
    "ㄱㅊ 아직 게임 안 끝남",
    "괜찮아, 이 정도면 생활 기스임"
  ]
}
```

## 말투를 재미있게 만드는 장치

재미는 내용만이 아니라 발화 방식에서 나온다.

### 리듬

- 짧게 끊기: "아. 이거네."
- 반복: "아냐아냐 그건 아냐."
- 점층: "오케이. 이해했고. 이제 망했다."
- 뜸들이기: "근데... 이게 좀 웃겨."
- 급발진: "아니 잠깐만 이거 국가적 사건인데?"

### 태도

- 능청
- 과장된 진지함
- 건조한 판정
- 억울함
- 딴청

### 변형

- 완곡화
- 축소
- 격상
- 의인화
- 사물화

예시:

```text
어렵다
→ 아 이거 쉽지 않음
→ 이건 난이도가 갑자기 정장 입고 들어왔는데요
```

## 데이터 수집 방법

현실적인 첫 데이터 소스는 유튜브 자막이다.

목표는 특정 인물 말투를 복제하는 것이 아니라, 여러 자막에서 사람들이 반응하는 말투 패턴을 뽑는 것이다.

중요하게 볼 구조:

```text
A가 말함
B가 짧게 받음
A가 웃음 / 계속 말함 / 반박함 / 분위기 식음
```

문장 자체보다 전후 반응을 태깅한다.

### 수집 파이프라인

```text
1. 유튜브 자막 SRT/VTT 수집
2. 발화 단위로 분리
3. 앞뒤 문맥 3~5턴 묶기
4. 짧은 반응 후보 추출
5. Annotator 모델이 상황/말투/반응 태그 생성
6. 사람이 일부 검수
7. Thinker/Speaker 학습 포맷으로 변환
```

## Annotator 모델

Annotator는 원문 대화를 보고 학습용 라벨을 생성하는 별도 모델이다.

입력:

```text
앞 문맥 + 대상 발화 + 뒤 반응
```

출력:

```json
{
  "context": "가벼운 실패를 말하는 상황",
  "speaker_state": ["민망함", "자기비하", "가벼운 불안"],
  "relationship": "친한 대화",
  "social_function": ["위로", "긴장 완화", "대화 유지"],
  "humor_permission": "light",
  "style_devices": ["축소", "능청", "짧은 비유"],
  "micro_style": ["ㄱㅊㄱㅊ", "아냐아냐", "망했다를 완곡화"],
  "avoid": ["조롱", "실패 확정", "과한 밈"],
  "expected_reaction": ["부담 감소", "가벼운 웃음", "대화 지속"]
}
```

## 내 말투 데이터의 역할

사용자 자신의 말투는 복제 대상이 아니라 style anchor로 쓴다.

특징:

- 아냐아냐
- 근데 그러면
- ~단말이지
- ~하겠는데?
- ㄱㄱ, ㄴㄴ, ㅇㅋ
- 생각이 중간에 방향을 바꾸는 구어체

목표는 한 사람 말투에 갇힌 모델이 아니라, 이 말투를 기준점으로 삼아 여러 스타일을 비교하고 조절하는 것이다.

## 학습 전략

대상 환경:

- GPU: RTX 3080
- RAM: 16GB
- 모델 후보: gemma4:e4b

현실적인 방식:

- 풀 파인튜닝은 피한다.
- 4-bit QLoRA 또는 LoRA를 사용한다.
- Thinker adapter와 Speaker adapter를 따로 학습한다.
- Thinker는 적고 정확한 라벨 중심 데이터로 학습한다.
- Speaker는 가능한 한 넓은 말투 데이터를 넣되 `style_control` 태그로 제어한다.
- 긴 컨텍스트보다 1024~2048 토큰부터 시작한다.
- 배치 사이즈는 작게 잡고 gradient accumulation을 사용한다.

초기 권장값:

```text
학습 방식: QLoRA 4-bit
LoRA rank: 8 또는 16
batch size: 1
gradient accumulation: 8~16
sequence length: 1024~2048
```

## 단계별 로드맵

### Phase 1: 프롬프트 프로토타입

- 학습 없이 Thinker/Speaker를 프롬프트로 구현한다.
- 입력 하나에 대해 판단 JSON과 답변이 잘 나오는지 확인한다.

### Phase 2: 샘플 데이터셋

- 자막 또는 직접 작성 예문 100~300개를 모은다.
- Annotator로 태그를 붙인다.
- 사람이 50~100개 정도 검수한다.

### Phase 3: 태그 체계 고정

- 너무 많은 분류를 줄인다.
- 자주 쓰이는 사회적 기능과 말투 장치만 남긴다.
- 좋은 답변, 나쁜 답변, 애매한 답변을 함께 저장한다.

### Phase 4: Thinker 학습

- 입력을 보고 JSON 판단을 출력하도록 LoRA 학습한다.
- 출력 안정성과 보수성을 먼저 평가한다.

### Phase 5: Speaker 학습

- 입력과 Thinker 판단을 보고 말맛 있는 답변을 생성하도록 학습한다.
- Speaker LoRA에는 다양한 유튜브 자막, 직접 작성 예문, 사용자 말투 anchor를 넓게 넣는다.
- 모든 샘플에 `source_style`, `energy`, `humor_level`, `dialogue_type`, `risk` 같은 컨트롤 태그를 붙인다.
- 상황극/콩트 데이터는 `sketch`로 분리하고 실제 대화형 데이터와 섞이지 않게 한다.
- 판단을 넘어서 과하게 까불지 않는지 확인한다.

### Phase 6: 연결 평가

- Thinker → Speaker 2단 호출로 실제 대화 테스트를 한다.
- 사람이 보기에 친근한지, 웃긴지, 무례하지 않은지 평가한다.

## 평가 기준

모델의 좋고 나쁨은 단순히 웃긴지로 보지 않는다.

- 상황 판단이 맞는가?
- 유머 허용 범위를 넘지 않는가?
- 짧은 반응이 자연스러운가?
- 대화가 이어지는가?
- 사용자가 덜 민망하거나 덜 외롭게 느낄 만한가?
- 심각한 상황에서 장난을 줄이는가?
- 초성/밈/비유가 과하지 않은가?

## 핵심 문장

재미있는 출력은 자유롭게, 분류와 판단은 보수적으로.

재미있는 말투를 학습시키는 것이 아니라, 재미가 허용되는 조건을 학습시킨다.

최종 목표는 "눈치 레이어 + 말맛 레이어"를 가진 한국어 마이크로스타일 대화 모델이다.
