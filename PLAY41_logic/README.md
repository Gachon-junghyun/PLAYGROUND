# PLAY41_logic

## 목적
"논리는 후천적으로 키울 수 있는가"에 답하기 위해, 기존 말싸움/토론 코퍼스(PLAY33 `data_argue_en`+`data_debate`, 163카드)에서 **이김(수사)이 아니라 옳음(truth-tracking)에 기여하는 논리 무브만** 역추출해 6축 프레임으로 묶고, 6개 현실 자리에 스트레스테스트해 "논리 훈련 플레이북"으로 구체화한다. (PLAY37/38과 동일 파이프라인.)

## 실행법
```powershell
# 1단계 산출물(scenario_findings.json)을 다시 만들려면 — Workflow 도구로 스크립트 실행
#   logic_stress_test.workflow.js 를 Claude Code의 Workflow 로 돌린다(서브에이전트 6×2).
#   * 신규 다운로드/설치 없음. PLAY33의 기존 카드/리포트를 입력으로 쓴다.

# 산출물 읽기
#   logic_playbook.md          ← 최종 결과물 (사람이 읽는 것)
#   scenario_findings.json     ← 워크플로우 raw (시나리오별 적용+검증)
```
의존성 설치 없음. 추가 모델/네트워크 호출 없음(워크플로우 서브에이전트만 사용).

## 입력 / 출력
- **입력:** PLAY33 코퍼스 — `data_argue_en/cards/E_b1~6.jsonl`(99) + `data_debate/cards/D_b1~4.jsonl`(64), 리포트 3개(`malssaum_playbook.md`, `debate_en_report.md`, `debate_report.md`). 이 PLAY는 그걸 **읽어서 종합**하지 import 하지 않는다(프레임 텍스트를 워크플로우 스크립트에 임베드).
- **출력:**
  - `logic_playbook.md` — 논리 6축 + 6개 자리 플레이북 + "논리는 키울 수 있는가" 결론
  - `logic_dialogues.md` — 플레이북 무브를 2인 대화 표본으로 굴린 데모(배치1 4개 + 배치2 명절/일상 말싸움 4개, 주석 포함, 픽션)
  - `scenario_findings.json` — 워크플로우 raw 결과

## 가정 & 제약
- **"논리"의 해석:** 사용자 질문("논리도 후천적으로 키울 수 있나")을 *truth-tracking(참을 좇는 추론)* 으로 해석했다. 말싸움 코퍼스는 대부분 *winning(이김)* 기술이라, 이 PLAY의 핵심 작업은 둘을 갈라내는 것이다. "이긴 것처럼 보이게 하지만 옳음엔 기여 0"인 무브(페이스 강탈·캐릭터 조롱·'감정적' 라벨·가스라이팅 등)는 **수사로 분류해 플레이북에서 제외**하고 "당했을 때 식별"용으로만 남겼다.
- **코퍼스 편향 = 출발점이자 한계.** 원천이 "이기는 토론" 영상(다수 owns/destroys 편집)이라, won이 실제 논파가 아니라 청중장악일 때가 많다. 화자분리(diarization) 없어 귀속은 문맥추론. 따라서 카드ID 근거는 *수사적 효과*의 표본이지 진위 판정이 아니다.
- **이건 LLM 서브에이전트의 현실 추론**이지 실측이 아니다. skeptic 단계가 교과서성을 걸렀지만 *합리적 가설*로 받고 본인 경험으로 보정할 것.
- 6개 자리(실시간 말싸움·정보평가·내 생각 점검·의사결정·윤리적 설득·선동/가스라이팅 방어)는 사용자 요구(말싸움·토론·말 잘하는 법)+논리 질문을 합쳐 해석한 것.
- PLAY 간 의존 금지 규칙 준수: PLAY33 데이터를 *읽기만* 하고 코드 import 없음.
