# PLAY33_yt_career_harvest

## 목적
키워드 하나(예: "카카오 네이버 삼성전자 개발자 취업")로 구독자 12만+ 유튜브 채널을 발견 → 신규 영상만 다운로드 → Whisper 전사 → Claude subagent가 **취업 팁·사고방식**을 추출 → 리포트로 종합하는 파이프라인. 데이터 수집은 Python CLI, 정리/팁/사고방식/리포트는 Claude Code가 직접 수행한다.

## 실행법

### 0. 사전 설치 (한 번만 — 코드 실행 경로 밖, 무거우니 미리)
```powershell
pip install yt-dlp faster-whisper
# ffmpeg 필요 (mp3 추출). 없으면: winget install Gyan.FFmpeg  또는 choco install ffmpeg
# GPU(CUDA) 전사를 쓰려면 그에 맞는 PyTorch/CUDA 환경이 이미 있어야 함.
```

### 주제 격리 (선택) — `data_<topic>/` 로 분리
여러 주제를 한 PLAY에서 섞지 않으려면 **회전 시작 전 env var 하나**만 깔면 된다. 그 회전의 01~03 + 카드/리포트가 전부 `data_<topic>/` 밑으로 격리된다 (`_common.py`의 `DATA_DIR` 한 곳에서 파생).
```powershell
$env:PLAY33_TOPIC = "career"   # → 모든 산출물이 data_career/ 로
# 설정 안 하면 기존 data/ 그대로 (하위호환).
# 현재 "대화" 데이터를 격리하려면: git mv data data_talk  후 항상 $env:PLAY33_TOPIC="talk" 로 실행.
```

### 1~3. 데이터 수집 (Python)
```powershell
cd PLAY33_yt_career_harvest

# 1) 키워드 → 12만+ 채널 발견
python scripts/01_discover.py "카카오 네이버 삼성전자 개발자 취업" --min-subs 120000

# 2) 채널별 최신 8개 → 신규만 큐잉
python scripts/02_fetch.py --from-channels data/channels.jsonl -n 8
#   제목 필터(온토픽만): 최신 40편 스캔 → 키워드 매칭, 채널당 최대 8편
python scripts/02_fetch.py --from-channels data/channels.jsonl -n 40 `
    --match "토론,말싸움,논쟁,논증,반박,설득,디베이트,말빨,언변" --keep 8

# 3) 다운로드 + Whisper 전사  (무거움 → background 권장)
python -u scripts/03_pipeline.py > data/run.log 2>&1
#   GPU 없으면: python scripts/03_pipeline.py --device cpu --compute-type int8 --model small
#   단건 테스트: python scripts/03_pipeline.py --url "https://youtu.be/xxxx"
```

### 4~5. 정리 / 리포트 (Claude Code)
`prompts/orchestrator.md` 를 Claude Code에게 주면 1~5단계를 끝까지 운전한다.
- Step 4: `data/manifest.jsonl` 의 영상을 batch로 나눠 **Agent(subagent) 병렬 호출**, 각 subagent에 `prompts/subagent_distill.md` 본문 전달 → `data/cards/<batch>.jsonl`.
- Step 5: 모든 카드를 종합 → `data/reports/career_report.md`.

**Whisper 없이 정리 단계만 테스트:** `data/transcripts/SAMPLE000001.txt` + `data/manifest.sample.jsonl` 로 subagent distill을 바로 돌려볼 수 있다.

## 입력 / 출력

| 단계 | 입력 | 출력 |
|---|---|---|
| 01_discover | 키워드 문자열 | `data/channels.jsonl` `{channel_id,name,url,subscribers}` |
| 02_fetch | channels.jsonl 또는 `--channel` (+ 선택 `--match`/`--keep`) | `data/queue.jsonl` `{video_id,title,url,channel}` (신규만, 제목필터 통과분) |
| 03_pipeline | queue.jsonl | `data/transcripts/<id>.txt` + `data/manifest.jsonl` + `data/run.log` |
| subagent (Step 4) | manifest + 자막 | `data/cards/<batch>.jsonl` (팁/사고방식 카드) |
| 종합 (Step 5) | cards/*.jsonl | `data/reports/career_report.md` |

증분 캐시: 처리한 video_id 는 `data/seen.json` 에 기록돼 다음 실행 때 자동 제외. `02_fetch.py --all` 로 무시 가능.

> **주제 격리 시:** env var `PLAY33_TOPIC` 를 깔면 위 표의 모든 `data/` 가 `data_<topic>/` 로 바뀐다. seen 캐시도 주제별로 분리돼 주제 간 영상이 안 섞인다.

## 가정 & 제약

1. **PLAY 독립.** 다른 PLAY나 HAN_LAB 코드를 import 하지 않음. yt-dlp/whisper 래퍼는 `scripts/_common.py`에 자체 포함.
2. **03_pipeline은 디스패치 45초를 넘는다.** 반드시 `_REFERENCE/long_running.md` 패턴(background + `run.log`의 `DONE`/`FAILED` 폴링)으로 돌릴 것. 03만 `faster_whisper`를 import 하므로 01/02는 whisper 미설치 상태에서도 동작.
3. **전사 기본값 = `large-v3` + `cuda` + `float16`** (RTX급 GPU 가정). GPU 없으면 모델 로드에서 `FAILED`를 찍고 종료하니 `--device cpu --compute-type int8 --model small`로 내려라.
4. **오디오만(mp3) 다운로드.** 전사에 영상이 불필요해 용량 절감. 영상 원본은 남기지 않음.
5b. **제목 필터(`02_fetch --match`)는 채널의 *최신 N편 안에서만* 작동한다.** 채널이 토론 영상을 최근에 안 올렸으면 0편이 나온다. `-n`(스캔 window)을 키우면 더 과거까지 뒤지지만 yt-dlp 호출이 늘어 느려진다. 키워드는 OR·부분일치·대소문자 무시.
5. **채널 발견은 검색 기반이라 노이즈가 섞인다.** 넓은 키워드("취업")는 뉴스 채널이 상위를 먹음 — 키워드를 좁히거나 `--min-subs`를 올려 정제. 실측(2026-05-30, "카카오 네이버 삼성전자 개발자 취업", search 20): 후보 19 → 12만+ 7개(MBCNEWS·YTN사이언스·SBS Biz·캐치TV·디지틀조선TV·취업사이다·키키티비). 개발자 실무 채널을 노리면 "신입 개발자 취업 후기" 류로 좁히는 게 낫다.
6. **정리/팁/사고방식/리포트는 LLM 호출이 아니라 Claude(메인)+subagent의 직접 작업.** 별도 ollama/외부 API 안 씀 (외부 API 금지 룰 자동 충족).
   - **주제 격리는 env var 방식.** `PLAY33_TOPIC` 미설정 = 기존 `data/`(하위호환). 한 회전(01→02→03)은 같은 env로 돌려야 경로 일관. 기존 "대화" 데이터는 라이브로 합성 중이라 자동 rename 안 함 — 마이그레이션(`git mv data data_talk`)은 합성 끝난 뒤 수동.
7. **검증 안 한 부분:** 실제 다운로드+전사(03)와 subagent distill(Step 4~5)은 GPU·네트워크·Agent 실행이 필요해 이 생성 턴에서 end-to-end로 돌리지 않음. 01(발견)과 전 스크립트 import/문법은 검증됨. 샘플 자막으로 Step 4 입력 형식만 확인 가능.
