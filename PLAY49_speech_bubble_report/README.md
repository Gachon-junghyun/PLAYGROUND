# PLAY49_speech_bubble_report — 말풍선 리포트

## 목적
한 줄: **"애널리스트가 내 차트 옆에서 말해준다."** 딱 열면 **채팅 창처럼** — 상단에 차트,
아래로 각 증권사 리포트가 **[이름 → 주장 → 근거 → 결론]** 으로 쫘라락 펼쳐져 스크롤로 다 보이는
데모. 클릭/팝업 없이 전부 노출. 상단 탭으로 종목 전환, 차트의 번호 핀을 탭하면 해당 메시지로 스크롤.

**현재 라이브 데모 = 삼성전자 · SK하이닉스 · 팔란티어(PLTR) · 엔비디아(NVDA) (4종목, KRW+USD).** AI
에이전트(서브에이전트)가 웹에서 2026-06 시점 실제 애널리스트 뷰(KB·한화·Goldman·Nomura·Wedbush·Morgan
Stanley·Jefferies·BofA 등)를 수집하고, **내가(클로드 코드 루틴) 주장/근거/결론으로 직접 정리**해 얹었다.
목표가·증권사·날짜는 실제, 가격선은 추정. 실시간 LLM API 호출 없음. (PLTR 매수$230/중립$205/매도$70,
NVDA 매수$285/매수$275/중립 — 의견 스프레드를 차트 핀 색으로 노출.)

> 대안 데이터셋: `build_data.py`를 돌리면 PLAY43 카드팩토리의 에너지/호르무즈 리포트로 data를 갈아끼울 수 있다
> (아래 §실행법 참고). 즉 **같은 화면, 데이터 소스만 교체** — 웹 에이전트(2종목) ↔ 카드팩토리(에너지).

## 실행법
프론트엔드 2개(창/브라우저)는 **같은 `data.json`/`data.js`** 를 본다. 그 data를 만드는 빌더가 2개다.

### A) 데스크탑 창 (권장 · 서버·인터넷·설치 전부 불필요)
파이썬 표준 내장 **Tkinter**만 쓴다. 더블클릭하면 네이티브 창이 뜬다.
```powershell
PLAY49_speech_bubble_report\run.bat       # 콘솔 없이 창만 (pythonw)  ← 가장 간단
# 또는
python PLAY49_speech_bubble_report\app.py
```

### B) 브라우저 (HTML 버전)
```powershell
start PLAY49_speech_bubble_report\index.html      # 더블클릭. 단, CDN 로딩에 인터넷 필요
```

### 데이터 빌더 (둘 중 하나로 data.json/data.js 생성 — 커밋돼 있어 안 돌려도 바로 뜸)
```powershell
# 1) 라이브: 삼성전자·SK하이닉스 (stocks/*.json = 에이전트 웹 리서치 결과)
python PLAY49_speech_bubble_report\build_stocks.py
# 2) 대안: PLAY43 카드팩토리 에너지/호르무즈 리포트
python PLAY49_speech_bubble_report\build_data.py
```
새 종목/리포트를 넣으려면 `stocks/<종목>.json`을 추가(또는 에이전트로 갱신)하고 `build_stocks.py` 재실행.

> **창 버전(A)은 오프라인 OK.** 브라우저 버전(B)만 React·Tailwind·Babel을 CDN에서 불러와 인터넷이 필요.

## 입력 / 출력
- **입력 — 라이브(2종목):** `stocks/*.json` — AI 에이전트가 웹에서 수집·정리한 종목별 리포트(주장/근거/결론·
  목표가 포함). 소스 오브 트루스. `build_stocks.py`가 읽어 조립.
- **입력 — 대안(에너지):** `../PLAY43_card_factory/data/inbox|cards/*` + `curated.json`(내가 정리한 주장/근거/결론).
  `build_data.py`가 읽음. 카드팩토리 산출물은 건드리지 않는다(읽기 전용).
- **중간 산출물:** `data.json`(창 app.py 용) + `data.js`(브라우저 `window.DEMO_DATA`). 빌더가 둘 다 생성,
  커밋돼 있어 빌드 없이 바로 뜬다. **마지막에 돌린 빌더의 데이터가 화면에 뜸**(둘이 같은 파일을 씀).
- **출력(화면):** 종목 탭 + 차트(번호 핀) + 애널리스트 메시지 채팅 피드(이름·주장·근거·결론) + 목표가·영향 배지.

### data.json / data.js 스키마 (멀티 종목)
```js
window.DEMO_DATA = {
  stocks: [ {
    ticker, name, unit, price, change, asof, note,
    series:  [ { date:"2026-06-12", value:2880000 }, ... ],   // 추정 가격선
    reports: [ {
      id, date, firm, source,                 // firm=증권사
      opinion, tone:"up|down|flat", newsImpact:±n,
      targetPrice,                            // 목표가(원) — 있으면 칩으로 표시, 없으면 null
      pinDate,                                // 발행일을 차트 거래일에 스냅한 값(차트 핀 위치). 범위 밖이면 없음→핀 생략
      title, claim, evidence:[{label,text}], conclusion,
      curated                                 // true=AI 에이전트가 정리 / false=자동추출 초안
    } ]
  }, ... ],
  meta: { generated_at, source, n_stocks, no_live_api:true }
}
```
> 하위호환: `stocks`가 없고 `subject/series/reports`만 있는 옛 스키마(=`build_data.py` 출력)도 두 프론트엔드가
> 자동으로 1종목으로 감싸 읽는다.

## 가정 & 제약 (가장 중요 — 검증 없이 진행한 부분)

### 라이브 2종목 데모 (삼성전자·SK하이닉스)
- **리포트·증권사·목표가·투자의견은 실제(웹 리서치), 가격선(series)은 추정.** 에이전트가 2026-06 시점 실제
  애널리스트 뷰를 수집(KB 550,000 / Goldman 480,000 / Nomura 590,000·삼성; KB 380만 / 한화 430만 / 노무라
  500만·하이닉스 등)했고 출처 URL을 `stocks/*.json`에 보관. **단 일별 종가(series)는 알려진 현재가·고점·
  폭락일(6/23 하이닉스 -12.5%)을 앵커로 보간한 추정치**라 정확한 OHLC가 아니다. 화면에도 "추정 가격선"으로 명시.
- **목표가 일부는 언론 인용·공격적 모델.** 예: 노무라 하이닉스 500만은 국내 보도 인용(원문 미확인), KB 삼성
  영업이익 375조는 매우 공격적 모델 — 각 리포트 본문/결론에 그 한계를 적어둠. 투자권유 아님, 데모용 큐레이션.
- **에이전트 파이프라인 = "리포트 갱신 + 파악".** 서브에이전트 2개가 WebSearch로 종목별 뷰를 모아 주장/근거/
  결론 구조로 반환 → `build_stocks.py`가 발행일을 차트 거래일에 스냅해 조립. 이게 ingest+distill을 두 종목에
  겨눈 것. 새 종목은 `stocks/<x>.json` 추가 후 재빌드.
- **발행일↔차트 정렬.** 리포트 발행일이 series 범위 밖(예: 삼성 Goldman 6/1·Nomura 5/15)이면 차트 핀을 만들지
  않고 피드에만 노출(거짓 핀 금지). 범위 안이면 가장 가까운 거래일로 스냅. PLTR은 3건이 다 찍히도록 series
  앞 6/05~6/10 구간을 추정 lead-in으로 늘려둠(priceNote에 명시).
- **통화 = 종목별 unit.** KRW(원)·USD(달러) 모두 지원 — 가격·목표가·차트축이 단위 따라 `원`/`$`로 표시.
  PLTR 목표가·현재가·축은 `$`. (이전 "원" 하드코딩 버그 수정.)
- **PLTR 목표가는 언론 인용.** Wedbush $230 / MS $205 / Jefferies $70은 보도 인용(원문 노트 미확인) — 각 결론에
  명시. 투자권유 아님.

### 에너지 대안 데모 (카드팩토리)
- **AI = 클로드 코드 루틴, API 미사용.** "AI 요약 3줄"은 PLAY43 카드팩토리가 **오프라인에서 미리
  증류해 둔 사고카드**(`attention_hook`/`reasoning_move`/`original_signal`)의 첫 문장을 뽑아 만든 것.
  런타임 LLM 호출 0. 로드맵의 "손절가 도달 시 리포트 자동 푸시"도 같은 모델 — cron으로 도는 클로드
  코드 루틴이 새 리포트를 증류해 `data.js`만 갈아끼우는 구조를 의도.
- **모의 가격선.** 카드팩토리 리포트는 **산업분석**이라 단일 종목 목표가가 없다. 그래서 종목 대신
  **"에너지 섹터(호르무즈 국면)" 모의 지수**를 그리고, 그 위에 실제 리포트를 얹었다. 가격값은 데모용
  (호르무즈 긴장→우상향 서사), 리포트(증권사·날짜·요약)는 전부 실데이터. 화면·README에 "모의"라고 명시.
- **테마 필터.** `build_data.py`는 카드가 달린 리포트 중 제목/소스에 에너지·호르무즈·유가 키워드가
  있는 것만 골라 마커로 쓴다(`THEME_KEYS`). 현재 3건: Seeking Alpha(6/10)·유진투자증권(6/11)·하나증권(6/12).
  다른 테마(방산·반도체 등)로 바꾸려면 `THEME_KEYS`와 `SERIES`를 교체하면 된다 — 단일 테마만 데모한다.
- **투자의견은 휴리스틱.** 리포트 본문에서 OVERWEIGHT/매수/중립 등 키워드를 정규식으로 잡아 매핑.
  못 잡으면 `주목(flat)`. 산업 리포트라 의견 표기가 들쭉날쭉 → best-effort.
- **주장/근거/결론 = AI 에이전트가 직접 정리(`curated.json`).** 핵심: 기계적 truncation이 아니라
  **클로드 코드 루틴(=나)이 원본 사고카드를 읽고 손으로 다듬은** 주장·근거·결론을 `curated.json`에 박아둔다.
  이게 소스 오브 트루스 → `build_data.py`가 자동추출 초안 위에 덮어쓴다. 버블 footer에 "AI 에이전트가 정리"
  표시. **새 리포트는 `curated.json`에 항목을 추가하기 전까지는 자동추출 초안**(카드 첫 문장 발췌, `…`)으로
  뜨고 "자동추출 초안"으로 표시됨 — 깨지지 않게 하는 fallback. 즉 "AI가 정리"의 정리 주체가 곧 이 루틴이다.
- **자동추출 초안 매핑(fallback).** curated 없을 때 — 주장=`attention_hook`, 근거=`reasoning_move`+
  `original_signal`, 결론=카드 `title`. 원문 발췌라 뉘앙스가 잘릴 수 있음. 전체는 `data/cards/*.jsonl`에.
- **레이아웃 = 채팅 피드.** 클릭→팝업이 아니라 전부 펼쳐 스크롤(사용자 요구). 차트 번호 핀 클릭 =
  해당 버블로 스크롤. 한 컬럼 메신저 느낌.
- **창 버전(app.py)은 이모지 미사용.** 윈도우 Tkinter 기본 한글 폰트(Malgun Gothic)에 이모지 글리프가
  없어 □(tofu)로 깨진다 → 차트 마커는 Canvas 도형(번호 핀), 아바타는 '증', 화살표는 ▲▼■ 로 대체.
  브라우저 버전(index.html)은 이모지 그대로 사용. 두 버전은 같은 데이터, 다른 표현.
- **창 버전 폰트 = Malgun Gothic 고정.** 다른 OS/폰트 미설치 환경이면 한글이 다른 폰트로 떨어질 수 있음
  (윈도우 가정).
- **제목 일부는 카드팩토리에 truncated로 저장됨**(예: "…이후 유" ← 유틸리티). 원본 저장값을 그대로
  존중(꾸며내지 않음).
- **타임프레임 토글(1D/1W/1M)** 은 모의 — series 뒤쪽 N개만 잘라 보여줄 뿐 실제 분봉 데이터는 없음.
- **PLAY 독립성:** 코드 import 없이 PLAY43의 *데이터 파일만* 상대경로로 읽는다. 카드팩토리를 깨지 않음.

## AI 에이전트 파이프라인 (개념)
```
[라이브 2종목]
서브에이전트(WebSearch) ── 종목별 애널리스트 뷰 수집 + 주장/근거/결론 정리
        │  stocks/삼성.json · stocks/하이닉스.json (목표가·출처 URL 포함)
        ▼
build_stocks.py   ── 발행일→거래일 스냅 + id 부여 → data.json / data.js
        ▼
app.py (창) / index.html (브라우저) ── 종목 탭 + 차트 핀 + [이름·주장·근거·결론] 피드
        ▼ (로드맵)
손절가/조건 트리거 ── 클로드 코드 cron 루틴이 관련 리포트 자동 푸시

[대안: 에너지]  PLAY43 카드팩토리 → curated.json → build_data.py → 같은 화면
```
